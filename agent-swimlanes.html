Text equivalent of the diagram: its nine stages and all eighteen contracted messages, in the order they are drawn. Delivery state is not shown here — no message below is claimed as sent, received or acted on.

  1. Decide — Manager → Owner: an open decision with its options, cost and what it blocks. Owner → Manager: the ruling — approved, deferred, or still pending.
  2. Assign — Manager → Worker: bounded assignment with an exact file lease.
  3. Build — Worker: changes only the leased files and runs scoped tests.
  4. Handoff — Worker → Manager: durable handoff — files, tests, hashes, limits.
  5. Review — Worker → CTO and Worker → CPO run in parallel and independently. CTO → CPO: findings cross the boundary with no silent substitution. CTO → Manager and CPO → Manager: separate technical and product receipts. Manager → Worker: CHANGES REQUIRED returns the slice to the worker.
  6. Integrate — Manager: integrates reviewed bytes — hash match, rerun checks, sync plans.
  7. Evaluate — Manager → Evaluator: evaluate the whole ledger, not a passing test count. Evaluator → Manager: INCOMPLETE / INVALID / COMPLETE report.
  8. Publish — Manager → Publisher: reviewed snapshot and expected remote baseline. Publisher → Manager: publication receipt with hosted bytes verified.
  9. Automation — Router → Coordinator: changed event payload, no interactive input. Coordinator → Manager: handled / blocked disposition — never a PASS.

Role boundaries

01 / Manager

Bounded assignment

Owns scope, prerequisites, acceptance and exact file leases.

Does not infer readiness from an idle pane.

02 / Worker

Build the leased slice

Changes assigned files; runs scoped tests.

Does not widen scope or accept its own work.

03 / Worker → manager

Durable handoff

Supplies files, tests, hashes and limits.

Editable input is UNSENT; a claim is not a receipt.

04a / CTO

Technical review

Independently checks contracts, implementation and tests.

Does not substitute for product acceptance.

04b / CPO

Product review

Independently checks behavior, source and scope.

Does not silently accept CTO work.

05 / Manager

Integrate reviewed bytes

Matches review hashes; copies declared files; reruns checks; syncs plans.

Unmatched receipts cannot close integration.

06 / Completion evaluator

Check the whole ledger

Checks gates, inventory, dependencies and evidence hashes.

Test counts do not finish a Quest or Campaign.

07 / Manager / publisher

Publish & verify

Validates snapshots and remote baseline; publishes; verifies hosted bytes.

A pushed commit is not a deployed, verified page.

What prevents false “done”

  • Handled means routing disposition, never PASS.
  • A bounded Step DONE does not mean Quest, Quest Line or Campaign DONE.
  • Tests prove their scope; a test count does not close a parent.
  • Pushed, deployed and hosted-bytes-verified are separate events.
  • Stale heartbeats do not prove active work.
  • Review receipt hashes must match integrated bytes.
  • Held, external, owner-only and unresolved decisions stay visible.
  • Personal Voice remains deferred beyond MVP.
